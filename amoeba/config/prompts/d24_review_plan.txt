# Check each point and report only real problems
1. Coverage: every requirement id appears in a step's "covers"; no requirement weakened (compare verbs).
2. Numbers: the derived figures are correct (recompute them) and used by the steps that need them.
3. Dependencies: depends_on is correct; independent steps are marked parallel; no step uses an input
   that no earlier step produces.
4. Depth: every step has do / output / done_when specific enough to execute and check.
5. Verification: at least one step verifies numbers, sources or test results and is done by a role that did not
   produce them; if missing, Verdict must be REVISE.
6. Context: constraints in the task (team size, budget, region, deadline) shape the plan.
7. Risks and decision points are real and linked to steps.
8. Capabilities: each step can actually be done with the tools the team will have or a requested capability.
9. User-only inputs: anything only the user or their company can supply (brand style, internal data, credentials)
   is an Open Question or a capability request, never an assumption.
10. Interpretation: when the task carries a "Working interpretation", does the plan's reading of the task match it
   (the same organisation, place, product or person)? A plan that reads a name differently, or researches other
   readings as if they were the subject, must be revised.
