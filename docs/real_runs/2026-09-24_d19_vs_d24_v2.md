# Box 2: d19 vs d24 prompts on the complex tasks, v2 (2026-09-24)

    python -m scripts.eval_draft --tasks tasks/draft_eval_complex.jsonl --repeats 3 --llm openai \
        --model <gemini-3.1-flash-lite | gemini-3.5-flash> --draft-prompts <d19 | d24> [--quality-gate]

This is the same comparison as `2026-09-23_d19_vs_d24.md` (v1): the same 3 complex tasks × 3 repeats, 9 drafts per cell,
on the same two models. It runs on the code at 84a9990, which carries the fixes from v1's caveats:

- D26: every fenced block of a section is read.
- D27: every drafting role gets 8192 tokens, a reply cut off at `length` is retried once with double the tokens, and reasoning tokens are traced.
- D28: the d24 Plan Observer must answer REVISE when there is no independent verification, and `draft_quality` computes `independent_verification`.
- D29: capability names are normalised.
- D30: derived numbers are matched as value + unit.

The d24 gate was also run once, on both models (`--quality-gate`, 9 drafts each). That is 54 drafts in all. The raw per-attempt data is in `2026-09-24_d19_vs_d24_v2.csv`. Gemini ignores `seed`, so the repeats vary, and a difference of one or two drafts is noise.

## What changed vs v1

| | v1 → v2, 3.1-flash-lite d24 | v1 → v2, 3.5-flash d19 | v1 → v2, 3.5-flash d24 |
|---|---|---|---|
| Drafts accepted | 9/9 → 9/9 | **7/9 → 9/9** (D26) | 9/9 → 9/9 |
| Replies cut off | 0 → 0 | **17 → 0** (D27) | 1 → 3, all retried |
| Derived numbers correct | 9/9 → 9/9 | 6/9 → 6/9 | 8/9 → 9/9 (v1 re-scored with D30: 8/9; the old string match said 7/9) |
| Consensus | 7/9 → 6/9 | 1/7 → 0/9 | 9/9 → 9/9 |
| Rounds | 2.11 → 2.56 | 3.00 → 3.00 | 1.44 → 1.33 |
| Tokens per draft | 18,928 → 23,550 (+24%) | 29,942 → 28,904 | 25,243 → 29,206 (+16%) |
| Capability requests per draft (as written) | 3.8 → 3.4 | 0.9 → 1.3 | 5.1 → 4.1 |

1. **The parser and token fixes did what they were for.**
   - With D26, 3.5-flash d19 lost no roles: 9/9 drafts were accepted (v1: 7/9).
   - With D27, no observer reply was cut off on d19 (v1: 17). The 3 cut-off d24 replies on 3.5-flash were each retried with 16,384 tokens and recovered.
   - The hidden reasoning is now visible: 12.6k tokens per 3.5-flash d19 draft, 5.4k per d24 draft.
   - With 3 full rounds on every d19 draft and nothing cut off, d19 still reached consensus 0/9 on both models. So v1's "cut-off replies cost d19 consensus" caveat was not the reason.
2. **The D30 matcher removed the one v1 false negative and found no new ones.** Re-scoring v1 changes exactly one draft: the GiB/TiB clickstream draft on 3.5-flash d24, 7/9 → 8/9. In v2, d24 derived every number correctly on both models (9/9, 9/9). d19 still never derives the clickstream storage (0/6).
3. **Telling the Plan Observer to require independent verification did not change its verdicts.**
   - Across the 35 ungated d24 rounds, the Plan Observer said REVISE once.
   - It approved all 13 final drafts that have no independent verification (8 on flash-lite, 5 on 3.5-flash).
   - Independent verification (the D28 check) is 1/9 on flash-lite and 4/9 on 3.5-flash.
   - The extra flash-lite rounds (2.11 → 2.56) come from the Agent Observer answering REVISE (13 of 23 rounds), not from the new plan rule.
4. **The gate works as a lever, but it cannot fix the failures in 3 rounds.**
   - It sent drafts back 19 and 18 times. Final drafts failing a hard check fell from 8/9 to 6/9 on flash-lite and from 5/9 to 4/9 on 3.5-flash.
   - The summariser failures were all fixed on flash-lite (3 → 0).
   - What remains is almost all independent verification. The planners answer the gate with a "Cross-Verification" step that the same specialists do jointly, each checking the other: for example, steps 1–2 by A+B, then step 3 "Cross-Verification" by A+B. By the rule as written (verifier roles ∩ producer roles of the depended-on steps = ∅), that is not independent, and 3 rounds are not enough for the planner to restructure.
   - On 3.5-flash the gate doubles the cost (62k vs 29k tokens per draft) and cuts consensus to 5/9. It is off by default for that reason.

## What got worse

- **Tokens per d24 draft rose**: +24% on flash-lite (18.9k → 23.6k, more Agent Observer REVISE rounds) and +16% on 3.5-flash (25.2k → 29.2k). On 3.5-flash, most of the rise is hidden reasoning, which the 8192-token room now lets the model spend, plus the 3 retries.
- **flash-lite d24 consensus 7/9 → 6/9**, and its summariser check went 7/9 → 6/9. Both are within noise at 9 drafts. flash-lite d24 drafts also got slightly smaller (3.0 roles / 3.0 steps).
- **3.5-flash d24 cut-off replies 1 → 3.** All three were recovered by the D27 retry, at extra cost.
- **The gate on 3.5-flash**: 2.1× tokens, 1.9× latency (127 s per draft), and consensus 9/9 → 5/9. One gated draft lost requirement coverage (8/9) and one its summariser.
- **Fewer capability requests on d24** (3.8 → 3.4 and 5.1 → 4.1 as written). After merging duplicates by canonical name, that is 2.9 and 3.6 distinct capabilities per draft. v1 was not normalised, so part of the drop is the model's variation between runs rather than lost needs.

## Caveats

- There are 9 drafts per cell. The gate runs once per model.
- The independent-verification check works at step level. A step done jointly by A and B, "each checking the other's figures", is never independent under the rule as written, even though real cross-review happens. Whether that should count is a design choice; the rule has not been loosened here.
- `requirements_covered` is still self-reported: it reads the planner's own `covers` lines.
- The rubric (D30) scores answers, and this run is Box 2 only. Only its number matcher was used here, through `derived_correct`. The rubric items are exercised once the same comparison runs through Box 3.
