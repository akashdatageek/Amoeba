## 2. Snowflake SQL (not executed)
It is designed to run as a Snowflake Task graph: dedup, then DAU, then the job-run marker. It starts with `ALTER SESSION SET TIMEZONE='UTC'`.
- **Parameters:**
  - `lookback_days`, a starting value of 3 days to tune to Kafka redelivery behaviour.
  - `business_date` defaults to yesterday UTC and can be passed in for backfills.
  - `window_start` is business_date minus the look-back.
  - `window_day` is the date of window_start.
- **Tables:** CLEAN.EVENTS (clustered by event_date), MART.DAU_BY_COUNTRY (day, country, dau, computed_at) and OPS.JOB_RUNS.
- **(1) Dedup by event_id.** The SQL is a MERGE inside a transaction:
```sql
MERGE INTO CLEAN.EVENTS t USING (
  SELECT event_id,user_id,country,event_type,event_ts,ingested_at,DATE_TRUNC('day',event_ts)::DATE AS event_date
  FROM RAW.CLICK_EVENTS WHERE ingested_at >= $window_start
  QUALIFY ROW_NUMBER() OVER (PARTITION BY event_id ORDER BY ingested_at) = 1 ) s
ON t.event_id = s.event_id
WHEN NOT MATCHED THEN INSERT (...) VALUES (...);
```
  - The earliest ingested_at wins.
  - `WHEN NOT MATCHED` is the anti-join against ids already loaded, so a redelivery on a later day inserts nothing. A rerun inserts no rows.
  - The ON clause deliberately has no event_date prune, because a late event may carry an old event_ts.
- **(2) DAU per UTC day and country.** It is an idempotent delete-and-insert in the same transaction:
```sql
DELETE FROM MART.DAU_BY_COUNTRY WHERE day >= $window_day;
INSERT INTO MART.DAU_BY_COUNTRY (day,country,dau,computed_at)
SELECT DATE_TRUNC('day', event_ts)::DATE AS day, COALESCE(UPPER(country),'UNKNOWN') AS country,
       COUNT(DISTINCT user_id), CURRENT_TIMESTAMP()::TIMESTAMP_NTZ
FROM CLEAN.EVENTS WHERE user_id IS NOT NULL AND event_date >= $window_day GROUP BY day, country;
```
  - A MERGE upsert form is included as a commented alternative. It cannot remove a (day, country) row that has disappeared, so delete-and-insert is primary.
- **(3) OPS.JOB_RUNS success row.**
  - It is the last task in the graph, so it is written only if (1) and (2) succeeded.
  - It records job_name 'dau_nightly', business_date, status 'SUCCESS', rows_in, rows_loaded, duplicates_removed and finished_at. The watchdog reads this row.
  - Caveat: in the Snowflake version, rows_loaded counts CLEAN rows with ingested_at inside the window. The sqlite version counts rows actually inserted. started_at is NULL in the marker; the orchestrator or task should set it.

## 3. sqlite3 equivalent (`pipeline_sqlite.py`)
The logic is the same.
- **Dedup:** `INSERT … SELECT … ROW_NUMBER() OVER (PARTITION BY event_id ORDER BY ingested_at) rn … WHERE rn=1 AND NOT EXISTS (SELECT 1 FROM clean_events c WHERE c.event_id = s.event_id)`.
  - sqlite has no QUALIFY, so the window function sits in a subquery.
  - clean_events has event_id as PRIMARY KEY.
- **DAU:** `DELETE FROM dau_by_country WHERE event_date >= :from_day`, then an INSERT of the date part of the ISO text, `COALESCE(UPPER(country),'UNKNOWN')` and `COUNT(DISTINCT user_id)`, grouped by day and country.
- **Transaction:** `run(con, window_start, from_day, business_date)` does everything in one `with con:` transaction and then inserts the job_runs row.
- **Loading:** `load_raw` turns empty CSV strings into NULL.
- **Dialect difference:** the UTC day comes from the date prefix of the ISO text (`substr`) rather than `DATE_TRUNC`. Timestamps are compared as ISO text.
