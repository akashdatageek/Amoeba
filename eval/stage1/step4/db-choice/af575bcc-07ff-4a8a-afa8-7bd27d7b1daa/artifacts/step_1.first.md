**Takeaways**
1. **Vendor skew.** The only source with explicit test settings (S4) is sponsored by a PostgreSQL vendor [S4]. The MongoDB page (S27) is MongoDB marketing [S27]. The rest are blogs with unverified methods. Treat every comparison as skewed, not as a verdict. None replaces the schema prototype run on our own data and queries.
2. **Wrong workload.** Nothing I fetched measures tenant-filtered aggregation dashboards at our load. The task gives 5,000 queries per minute across all tenants, which is 5,000 / 60 = 83.3 QPS. The available material is OLTP or qualitative [S4][S2][S3]. I found no independent analytics, time-series or multi-tenant benchmark in this pass.
3. **Operational details outweigh headline ratios.** Connection pooling matters for PostgreSQL [S4]. Tuning level and instance size change the outcome. We control both in the prototype.
4. **JSONB vs documents.** Sources argue that PostgreSQL JSONB can cover document-style events [S14][S3]. None gives verified numbers for tenant-scoped aggregations. The prototype should test event ingest and dashboard aggregates on both databases. It should record p95 latency and storage ratios, which feed the cost model.
5. **Recency and dating.** No page gave a publication date [S38]. Only title years (2025, 2026) are known, so the evidence cannot be shown to be fresh. Treat the whole table as low-confidence background.
