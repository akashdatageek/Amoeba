## AlloyDB for PostgreSQL pricing

This page contains information about pricing for AlloyDB for PostgreSQL.

Pricing for AlloyDB for PostgreSQL is transparent and predictable, with no expensive, proprietary licensing and no opaque I/O charges. It is composed of the following charges:

*   [CPU and memory pricing](https://cloud.google.com/alloydb/pricing#cpu-mem-pricing)
*   [Database storage pricing](https://cloud.google.com/alloydb/pricing#storage-pricing)
*   [Backup storage pricing](https://cloud.google.com/alloydb/pricing#backup-storage-pricing)
*   [Networking pricing](https://cloud.google.com/alloydb/pricing#networking-pricing)
*   [Extended Support](https://cloud.google.com/alloydb/pricing#extended-support-pricing)

AlloyDB has a unique architecture to help users seamlessly scale storage and compute. Each AlloyDB deployment is organized as a cluster. A cluster includes all of the database storage and the compute resources in a region that serve a particular workload. A cluster has compute resources called instances, including primary instances and read pools. For high availability and horizontal scalability, instances have multiple nodes. Unlike typical PostgreSQL deployments, all of the instances deployed in a cluster share a single, horizontally scalable storage layer in the region.

For AlloyDB for PostgreSQL, VM memory, storage, and data transfers are calculated in gigabytes (GB), where 1 GB is 2 30 bytes. This unit of measurement is also known as a[gibibyte (GiB)](https://wikipedia.org/wiki/Gibibyte).

### CPU and memory

Compute resources for AlloyDB for PostgreSQL are organized as instances, and are priced per vCPU and GiB of memory. When you create an instance, you choose the number of CPUs and the amount of memory you want, up to 288 vCPUs and 2232 GiB of memory per node. A zonal primary instance uses one node. A high availability primary instance uses two nodes, one for the active primary and a second for the in-region standby. AlloyDB read pool instances can contain up to 20 nodes. CPU and memory pricing varies by location. Select your region in the dropdown on the pricing table.

AlloyDB supports multiple machine series. You can use different machine series across instances in your cluster, and switch between machine series with a simple, non-disruptive update operation. For more information about machine series and their regional availability, see [Choose an AlloyDB machine type](https://cloud.google.com/alloydb/docs/choose-machine-type).

AlloyDB also offers committed use discounts (CUDs) for CPU and memory resources when you commit to continuously use databases for a one- or three-year term. The pricing table below illustrates effective pricing per vCPU and per GiB of RAM after CUDs are applied. For more information about these commitments, see [Committed use discounts](https://cloud.google.com/alloydb/cud).
